조사일: 2026-09-19

이 문서는 개선 전 화면을 검토한 기록입니다. 화면 링크는 당시 커밋에 고정되어 있으며, 이후 구현·실제 앱 검증 결과는 [3.1.0 QA](../QA-3.1.0.md)에 기록합니다.

## 검토 방법과 근거 수준

공식 Obsidian 개발 문서와 W3C 원문을 현재 기준으로 확인했습니다. 각 제안은 실제 화면·코드에서 확인한 사실과 디자인 판단을 구분하여 기록합니다. 외부 제품 사례는 방향을 비교하는 참고 자료이며, Icon Fairy 사용자에게 동일한 효과가 발생했다는 증거로 사용하지 않습니다.

- **직접 관찰:** 현재 저장소의 화면 이미지와 소스에서 확인한 배치, 문구, 크기, 상호작용 정의입니다. 정적 이미지로는 실제 키보드 이동, 스크린 리더 출력, 운영체제별 터치를 판정하지 않습니다.
- **공식 기준:** Obsidian의 플러그인 UI 안내와 WCAG의 웹 접근성 성공 기준입니다. WCAG 본문은 규범 문서이고, WAI-ARIA APG 패턴 및 Understanding 문서는 적용을 돕는 설명입니다.
- **개선 제안:** 위 근거를 Obsidian 안의 HTML 기반 플러그인에 적용한 디자인 판단입니다. 별도 사용자 조사나 실제 앱 측정 전에는 사용성 개선량 또는 접근성 준수를 확정하지 않습니다.

화면 근거는 2026-09-13에 Obsidian 1.13.7 라이트 모드에서 촬영한 현재 README 이미지 9장입니다. 촬영 환경은 [기존 QA 기록](../QA.md#folder-heart-artwork-and-light-screenshots--2026-09-13)에서 확인했습니다. 모바일 이미지는 390 × 820 CSS px의 공식 데스크톱 모바일 에뮬레이션입니다. 이번 조사에서는 저장된 이미지를 모두 다시 열어 소스와 대조했으며, 새 실기기 테스트나 사용자 인터뷰를 진행한 것은 아닙니다.

## 이전에 해결한 문제는 유지합니다

[2026-08-19 UX/UI 조사 및 구현 기록](ux-ui-design.md)에 따르면 모달 제목·대상 설명, 탭 역할 및 키보드 이동, Random 명칭, 업로드 키보드 조작, 항목별 삭제 이름, 일괄 가져오기 이름 보존, 설정 자동 저장, 주석 삭제와 저장의 분리, 좁은 화면 대응은 이미 구현됐습니다. 이를 새로 발견한 결함이나 새 기능 제안으로 다시 계산하지 않습니다. 현재 검토에서는 해당 개선을 유지하면서 시각적 위계, 문구의 의미, 조작 영역과 상태 표현에 남은 여지가 있는지 봅니다.

## 공식 자료에서 도출한 여섯 가지 검토 기준

### 1. Obsidian의 테마와 어울리는 화면을 유지합니다

Obsidian은 플러그인의 사용자 지정 요소에 내장 CSS 변수를 사용하면 기본 UI와 일관되고 커뮤니티 테마와 호환되는 외형을 만들 수 있다고 안내합니다. [Obsidian — About styling](https://docs.obsidian.md/Reference/CSS%20variables/About%20styling)

**적용 판단:** 배경·테두리·본문·보조 문구·강조색을 앱의 테마 변수로 연결하는 방향을 유지합니다. 브랜드 로고의 주황·보라를 모든 버튼과 카드에 고정 적용하기보다, 로고는 브랜드를 식별하고 조작 요소는 사용자의 테마에 맞추는 편이 적절합니다. 라이트 화면에서 보기 좋다는 이유만으로 다크·커뮤니티 테마에서도 대비가 충분하다고 추정하지 않습니다.

**확신도:** 공식 원칙은 높음. 구체적인 색·간격의 개선 효과는 현재 화면과 두 테마 비교 후 판단합니다.

### 2. 설정 제목과 문구는 Obsidian의 규칙을 따릅니다

Obsidian 공식 체크리스트는 설정 섹션이 여러 개일 때만 제목을 사용하고, 제목에 불필요한 “settings”·“options”를 붙이지 않으며, UI 문구에 sentence case를 사용하도록 안내합니다. 설정 제목에는 직접 `<h1>`·`<h2>`를 넣는 대신 API의 `setHeading()` 사용을 권장합니다. [Obsidian — Plugin self-critique checklist, User interface](https://docs.obsidian.md/oo/plugin#User%20interface)

**적용 판단:** 설정이 많지 않다면 꾸밈용 섹션 제목을 늘리지 않습니다. 정말 다른 목적의 항목을 나눌 때만 짧은 제목을 사용합니다. 각 행은 이름만 읽어도 바뀌는 대상이 보이도록 하고, 설명은 범위·단위·결과 중 필요한 정보로 줄입니다. 단순 문구·배치 수정이며 설정 자체를 추가하는 제안은 아닙니다.

**확신도:** 공식 UI 규칙은 높음. 현재 제목의 중복 여부와 설명의 난이도는 화면별 판단이 필요합니다.

### 3. 모달은 제목, 작업 대상, 현재 할 일을 명확히 보여 줍니다

WAI-ARIA APG의 모달 패턴은 이름 있는 대화상자, 내부로 이동하는 초기 포커스, 내부 Tab 순환, Escape 닫기, 닫은 뒤 적절한 위치로 포커스 복귀를 설명합니다. 닫기 또는 취소 버튼을 눈에 보이게 제공하는 것도 권장합니다. [W3C APG — Dialog (Modal) Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

**적용 판단:** 기존 모달 제목과 대상 설명을 유지하되 제목·대상·도움말이 경쟁하지 않도록 글자 크기와 간격을 정돈합니다. 추가 확인 단계가 있는 가져오기·편집 화면은 주요 완료 버튼과 취소를 구분합니다. 즉시 적용되는 아이콘 선택창에 불필요한 확인 버튼을 더하는 제안은 아닙니다. “주요 버튼은 하나만 강조한다”는 시각적 위계 판단이며 APG가 요구하는 버튼 개수 규칙은 아닙니다.

**확신도:** 모달의 상호작용 기준은 높음. 화면의 시각적 위계 개선은 중간이며 실제 화면 근거와 함께 제시합니다.

### 4. 카드 선택과 관리 버튼의 의미가 구분되어야 합니다

APG 버튼 패턴은 버튼의 외형·역할이 수행하는 동작과 맞아야 하며, 접근 가능한 이름과 Enter·Space 활성화를 제공해야 한다고 설명합니다. 아이콘만으로 표현한 버튼에도 동작을 전달하는 이름이 필요합니다. [W3C APG — Button Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/)

**적용 판단:** 카드의 큰 영역이 아이콘을 적용하고 작은 버튼이 라이브러리에서 삭제한다면, 두 결과를 시각적으로 분리하는 것이 좋습니다. 삭제 버튼의 접근 가능한 이름을 이미 제공한 사실과, 일반 사용자가 버튼의 위치·의미를 쉽게 알아보는지는 별도로 봅니다. 현재 파일의 아이콘 지정 해제와 라이브러리 항목 삭제도 문구만으로 구별되는지 확인합니다. 특정 확인창·실행 취소 기능의 신설은 이번 범위에 포함하지 않습니다.

**확신도:** 버튼 의미·이름·키보드 기준은 높음. 카드 안 관리 동작의 배치 개선은 현재 화면을 근거로 판단합니다.

### 5. 아이콘의 그림 크기와 실제 클릭 영역을 구분합니다

WCAG 2.2의 2.5.8은 포인터 대상에 최소 24×24 CSS px 또는 명시된 예외를 적용합니다. 작은 대상도 주변 간격 등으로 예외를 충족할 수 있으므로, CSS에 `20px`가 있다는 사실만으로 실패라고 단정하면 안 됩니다. [WCAG 2.2 — Target Size (Minimum)](https://www.w3.org/TR/WCAG22/#target-size-minimum), [W3C — 크기·간격 예외 해설](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

**적용 판단:** 삭제·제거·닫기처럼 작은 버튼은 glyph 크기보다 실제 hit area를 확인합니다. 특히 카드의 적용 영역과 관리 버튼이 가까운 위치에서는 각 대상의 실제 경계와 간격을 함께 측정합니다. 필요한 경우 그림은 작게 유지하고 버튼 패딩을 넓힐 수 있습니다. 레티나 스크린샷의 이미지 픽셀을 CSS px로 취급하지 않습니다. 44px는 24px 최소 기준과 같은 의무 기준으로 표현하지 않습니다.

**확신도:** 크기 기준과 예외의 구분은 높음. 현재 앱의 충족 여부는 렌더링된 경계·간격 측정 전에는 미확정입니다.

### 6. 키보드 포커스는 hover와 별도로 확인합니다

WCAG 2.4.7은 키보드 포커스가 보이는 조작 방식을 요구합니다. W3C 해설은 어느 요소가 포커스를 받았는지 알 수 있어야 하며 표시가 시간 제한으로 사라져서는 안 된다고 설명합니다. [WCAG 2.2 — Focus Visible](https://www.w3.org/TR/WCAG22/#focus-visible), [W3C — Focus Visible 해설](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)

**적용 판단:** hover 배경만 있는지 확인하고, Tab으로 이동할 때 카드 선택·삭제·검색·탭·업로드·취소 버튼의 포커스 표시가 각각 보이는지 확인합니다. 사용자 지정 CSS에 `:focus-visible` 규칙이 없더라도 Obsidian 기본 스타일에서 표시할 수 있으므로, 소스 검색만으로 포커스가 없다고 판정하지 않습니다. 현재 선택 상태와 키보드 포커스는 다른 상태로 보여 주는 편이 명확합니다.

**확신도:** 포커스 가시성 기준은 높음. 실제 포커스 표시·색 대비는 실행 환경에서 확인해야 합니다.

## 현재 화면·소스 관찰

### 1. 카드의 선택과 관리 동작을 분리합니다 — P1

**관찰:** [모바일 화면](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/assets/icon-fairy-mobile.png)에서 각 카드 오른쪽 위에 작은 `×`가 항상 표시됩니다. 버튼은 항목별 접근 가능한 이름을 이미 갖고 있지만, 눈에 보이는 기호만으로는 닫기·지정 해제·라이브러리 삭제를 구분하기 어렵습니다. 소스상 이 버튼은 라이브러리 항목을 지우고, 해당 항목을 가리키는 파일·폴더의 `iconMap` 지정도 해제합니다. 이 클릭 핸들러에는 확인 단계가 없습니다. 이름 변경은 포커스 가능한 버튼이 아닌 이름 `div`의 `dblclick`에 연결돼 있습니다. [카드 동작 소스](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/src/ui/CustomTab.ts#L149-L197)

**제안:** 카드 본체는 지금처럼 아이콘을 적용하게 두고, 이름 옆의 명시적인 항목 메뉴에 기존 `Rename`과 `Delete from library`를 배치합니다. 더블클릭은 보조 단축 동작으로 남길 수 있습니다. 삭제에는 휴지통 기호와 대상 이름을 사용하고, 현재 파일의 지정만 해제하는 `Remove assigned icon`과 문구를 구분합니다. 모바일에서도 메뉴 버튼이 보여야 하며 Tab·Enter·Space로 접근할 수 있어야 합니다.

**판단:** 작은 삭제 버튼을 가장 쉬운 선택 동작 바로 옆에 노출하는 구조부터 개선하는 것이 좋습니다. 현재 삭제 버튼의 CSS 크기는 24 × 24px입니다. 이를 곧바로 WCAG 실패라고 판정하지 않았습니다. 새 배치를 비교할 때는 모바일 관리 버튼의 실제 조작 영역을 44 × 44 CSS px 정도로 확보하는 안을 권합니다. 이 수치는 본 검토의 사용성 목표입니다. 실행 취소·복구 시스템은 이번 제안에 포함하지 않습니다. [현재 크기와 배치](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/styles.css#L276-L298)

### 2. 검색창과 Random의 시각적 역할을 정돈합니다 — P1

**관찰:** [라이브러리](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/assets/icon-fairy-library.png)와 [모바일 화면](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/assets/icon-fairy-mobile.png)에서 검색 영역의 외곽선 안에 입력창이 다시 들어간 모양이 보입니다. 모바일에서는 바깥 강조선과 안쪽 두꺼운 회색 선이 동시에 보여 특히 복잡합니다. 검색과 Random이 한 줄에 있어 좁은 화면에서는 입력 영역도 줄어듭니다. 소스는 외곽 `focus-within` 강조와 내부 input 스타일을 각각 정의합니다. 캡처만으로 Obsidian·OS·플러그인 중 어느 스타일이 추가 테두리를 만드는지는 확정하지 않았습니다. [검색 스타일](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/styles.css#L94-L161)

**제안:** Obsidian 기본 검색 입력 형태에 맞추고, 포커스된 조작 대상을 알아볼 수 있는 일관된 강조 표시를 사용합니다. Random은 이름을 유지한 보조 버튼으로 분리하거나 더 가볍게 표시합니다. 모바일에서는 검색 입력에 우선적으로 너비를 배분합니다. 키보드 포커스를 없애는 방식으로 테두리를 정리해서는 안 됩니다.

**추가 문구 정리:** 저장된 항목을 고르는 탭은 `Icons` 대신 `Library`, 검색 안내는 `Search icons`처럼 짧게 표현하는 안이 적절합니다. 검색 결과가 없는 경우와 라이브러리가 비어 있는 경우는 현재 같은 빈 상태 문구를 사용하므로, 각각 “검색어를 바꿔 주세요”와 “Upload에서 첫 아이콘을 추가하세요”에 해당하는 안내로 구분합니다. 새 검색 기능을 추가할 필요는 없습니다. [빈 상태 소스](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/src/ui/CustomTab.ts#L119-L135)

### 3. 모달 높이를 내용에 맞추고 반복 문장을 줄입니다 — P1

**관찰:** [7개 아이콘의 라이브러리](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/assets/icon-fairy-library.png)에서는 두 번째 줄 아래에 넓은 빈 공간이 남습니다. [단일 업로드 미리보기](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/assets/icon-fairy-upload.png)도 완료 버튼 아래 공간이 큽니다. 본문에 `height: 360px`, `min-height: 320px`가 지정돼 있습니다. 제목 `Choose an icon` 다음 설명에서 같은 문장이 반복되며, 모바일에서는 제목·대상·탭·검색·도움말이 카드보다 먼저 상당한 공간을 차지합니다. [높이 정의](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/styles.css#L176-L182)

**제안:** 카드가 적거나 단일 이미지를 미리 볼 때는 콘텐츠에 맞게 창 높이를 줄이고, 항목이 많을 때만 제한된 본문 영역을 스크롤하게 합니다. 검색어를 입력할 때마다 창이 급격히 늘었다 줄지 않도록 검색 중 높이 변화는 억제하는 편이 좋습니다. 대상 설명은 `For “Welcome to Icon Fairy.md”`처럼 짧게 만들되 파일명은 남깁니다. 이름 변경이 명시적인 메뉴로 옮겨지면 상시 노출된 더블클릭 안내도 줄일 수 있습니다.

**유지할 점:** 아이콘 이름과 64px 카드 버튼 자체를 무조건 축소하지 않습니다. 첫 카드까지의 반복 설명과 불필요한 빈 공간을 먼저 줄이고, 탭 변경 시에는 적절한 최소 높이를 유지합니다. 현재 모바일 캡처에는 수평 넘침이 보이지 않으므로 “모바일 레이아웃이 깨졌다”는 지적은 아닙니다.

### 4. 이미 적용된 아이콘을 표시합니다 — P2

**관찰:** 샘플 파일에는 folder-heart 아이콘이 이미 적용돼 있지만, [선택창](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/assets/icon-fairy-library.png)의 해당 카드에는 현재 지정 상태를 구분하는 표시가 없습니다. 카드 렌더링에도 현재 대상의 지정 상태를 비교하는 분기가 없습니다. [카드 렌더링](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/src/ui/CustomTab.ts#L143-L173)

**제안:** 파일·폴더에 현재 지정된 라이브러리 항목이 있으면 얇은 강조 테두리와 체크 또는 `Current` 문구를 표시합니다. 색상만으로 상태를 전달하지 않고, 키보드 포커스와도 구별합니다. 현재 지정 대상이 없는 인라인 삽입에서는 이 표시를 생략합니다. 카드 선택 후 바로 적용되는 기존 동작을 유지하며 저장 버튼을 추가하지 않습니다. 기존 상태를 더 잘 보여 주는 변경입니다.

### 5. 업로드 결과를 문구와 미리보기로 설명합니다 — P2

**관찰:** [단일 업로드](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/assets/icon-fairy-upload.png)는 `Apply`와 `Save to library` 체크박스를 사용하고, [여러 파일](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/assets/icon-fairy-batch-import.png)은 `Import 3 icons`로 라이브러리에 추가합니다. 단일 파일의 적용과 일괄 추가는 결과가 다릅니다. SVG에서는 저장 체크박스가 선택된 채 비활성화되지만 이유를 설명하는 문구가 없습니다. [단일 업로드 동작](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/src/ui/UploadTab.ts#L258-L345), [일괄 가져오기 결과](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/src/ui/UploadTab.ts#L438-L549)

**제안:** 파일에 적용하는 문맥에서는 `Apply icon`, 일괄 추가는 `Add 3 icons to library`처럼 결과가 드러나는 문구를 사용합니다. 라이브러리 저장에는 “다른 파일에서도 다시 선택할 수 있도록 저장”한다는 짧은 설명을 붙이고, SVG의 고정 저장 상태에도 이유를 안내합니다. 인라인 삽입 문맥이라면 적용 문구 대신 삽입 문구가 맞습니다. 실제 저장 규칙이나 기본값을 바꾸는 제안은 아닙니다.

**시각 정리:** 일괄 목록의 PNG·SVG 배지는 현재 주요 완료 버튼과 같은 강조색입니다. 파일 형식은 중립적인 보조 배지로 낮추고, 아이콘·편집할 이름·완료 버튼 순으로 시선이 가게 합니다. 단일 업로드의 `SIDEBAR`·`EDITOR` 두 미리보기는 배경색만 약간 다른 큰 타일이므로, 기존 미리보기를 탐색기 행·본문 줄처럼 적용 맥락과 실제 표시 크기를 보여 주는 형태로 다듬을 수 있습니다. 별도 설정이나 미리보기 모드를 늘릴 필요는 없습니다.

### 6. 주석 편집의 공간과 버튼 비중을 조절합니다 — P2

**관찰:** [주석 화면](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/assets/icon-fairy-annotation.png)은 편집 영역과 미리보기가 잘 구분되고 삭제도 저장과 떨어져 있습니다. 다만 한 줄짜리 주석에도 9행 편집 영역과 미리보기의 최소 높이가 적용되고, 빨간 삭제 버튼이 보라색 저장 버튼과 비슷하게 강합니다. `⌘↵ to save` 문구는 고정 문자열인데 실제 단축키 등록은 `Mod+Enter`입니다. Windows 화면을 이번에 실행해 확인한 것은 아닙니다. [편집창과 안내](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/src/ui/InlineAnnotationModal.ts#L46-L68), [단축키 등록](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/src/ui/InlineAnnotationModal.ts#L115-L123)

**제안:** 짧은 주석의 초기 높이를 낮추되 사용자가 충분히 편집·스크롤할 수 있게 하고, 좁은 화면에서는 키보드가 열린 상태에서도 완료 버튼에 접근할 수 있도록 배치합니다. 저장은 주요 채움 버튼, 삭제는 분리된 텍스트 또는 윤곽 버튼으로 표현하면서 위험 동작임을 드러내는 문구·색을 유지합니다. 단축키 안내는 Mac에서 `⌘ Enter`, Windows·Linux에서 `Ctrl Enter`로 맞춥니다. 미리보기 탭이나 새 편집 기능은 제안하지 않습니다.

### 7. 설정·명령·우클릭 메뉴는 기본 UI를 유지합니다 — P3

**관찰:** [설정](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/assets/icon-fairy-settings.png)은 세 항목으로 간결하고, 크기 값 `24`와 자동 저장 안내가 이미 보입니다. [prefix 설명](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/src/settings.ts#L65-L84), [파일 메뉴](https://github.com/t1seo/icon-fairy/blob/f64cf528d99ff4b90a1225ecd3c5ae47e4f9721b/src/features/ContextMenu.ts#L15-L28)
